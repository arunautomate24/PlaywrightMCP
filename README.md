## Application Overview

The application under test is **[Swag Labs (SauceDemo)](https://www.saucedemo.com/)**, a public demo e-commerce site.

- **Login page (`/`)** – Username and Password textboxes plus a Login button. Valid usernames (`standard_user`, `locked_out_user`, `problem_user`, `performance_glitch_user`, `error_user`, `visual_user`) all share the password `secret_sauce`.
- **Products page (`/inventory.html`)** – shown after a successful login; has a "Products" header, sort dropdown, product list with "Add to cart" buttons and a cart button.
- **Failed logins** stay on `/` and show a dismissible alert starting with `Epic sadface:`.

The project is a Playwright + TypeScript framework using the Page Object Model, built with the help of AI agents driving the Playwright MCP server.

### Tech stack

| Area | Details |
|------|---------|
| Test runner | `@playwright/test` (TypeScript, Node 20+) |
| Browser project | `chromium` using locally installed Google Chrome (`channel: 'chrome'`) |
| Reporter | Playwright HTML report (`playwright-report/`) |
| CI | GitHub Actions – [playwright.yml](.github/workflows/playwright.yml) |
| AI tooling | GitHub Copilot custom agents + Playwright Test MCP server |

### Project structure

| Path | Purpose |
|------|---------|
| `src/pages/` | Page objects (`BasePages.ts`, `LoginPage.ts`, `InventoryPage.ts`) |
| `src/fixtures/base.ts` | Custom `test` fixture extending Playwright's base test |
| `tests/` | Spec files (`auth/`, `seed.spec.ts`, `example.spec.ts`) |
| `tests/data/users.json` | Test data (standard and locked-out users) |
| `specs/` | Markdown test plans generated by the planner agent |
| `.github/agents/` | Planner, Generator and Healer agent definitions |
| `.vscode/mcp.json` | MCP server configuration |
| `AGENTS.md` | Project rules for AI agents (locators, page objects, assertions) |

### Running the tests

```bash
npm install
npx playwright install
npx playwright test                 # run everything
npx playwright test tests/auth      # run the SauceDemo login tests
npx playwright show-report          # open the HTML report
```

## How Playwright MCP Is Used

The Playwright Test MCP server is configured in [.vscode/mcp.json](.vscode/mcp.json) and started with `npx playwright run-test-mcp-server`. It gives GitHub Copilot a real browser (accessibility snapshots, clicks, typing, navigation) and test-runner tools. Three custom agents in [.github/agents/](.github/agents) use it in sequence:

| Step | Agent | Role | Key MCP tools | Output |
|------|-------|------|---------------|--------|
| 1 | `playwright-test-planner` | Explores the app in a browser and writes a test plan | `planner_setup_page` (uses `tests/seed.spec.ts`), `browser_snapshot`, `browser_click`, `browser_type`, `planner_save_plan` | [specs/saucedemo-login.md](specs/saucedemo-login.md) |
| 2 | `playwright-test-generator` | Executes each plan step live and records it as a spec | `generator_setup_page`, `browser_*` actions, `generator_read_log`, `generator_write_test` | Spec files under `tests/` |
| 3 | `playwright-test-healer` | Runs failing tests, inspects the page and fixes them | `test_run`, `test_debug`, `browser_snapshot`, `browser_generate_locator`, `browser_console_messages`, `browser_network_requests` | Repaired specs |

Project rules in [AGENTS.md](AGENTS.md) and [.github/copilot-instructions.md](.github/copilot-instructions.md) keep generated code consistent: locator priority (`getByRole` → `getByLabel` → `getByTestId` → `getByText`), page objects with no assertions, web-first assertions only, and test data loaded from `tests/data/`.
